# Project Context

Ola AI Data Agent began as a Python project containing LangGraph workflows for ETL and PostgreSQL analysis. The web application is in progress: a mock-by-default FastAPI foundation, Workspace, ETL Studio, and SQL Analyst UI are present. Server-gated live agent dispatch exists but is not fully verified; the SQL UI is build-verified and fake-agent tested, while browser and controlled database permission checks remain open.

[`BUILD_PLAN.md`](BUILD_PLAN.md) is the canonical product blueprint and implementation roadmap. It defines the intended architecture, proposed API contract, security requirements, generated-file convention, phase order, and acceptance criteria. [`README.md`](README.md) documents the current repository and existing workflows.

### Repository structure cleanup — 2026-10-20

The FastAPI app, agents, shared schemas, utilities, React frontend, tests, local `data/`, and generated `app_data/` remain separate at the repository root. Standalone scripts are under `scripts/database/` and `scripts/examples/`; tracked workflow PNGs and graph generators use `docs/diagrams/`. The loader and example resolve project data paths from the repository root. `.gitignore` excludes generated datasets, local review artifacts, Python environments, frontend build output, app data, and the removed schema sample dump. `utils/database.py` now exposes metadata only; the local schema report is written under ignored `app_data/`. The database loader requires `--confirm-truncate` and is protected by a main guard, but remains destructive when deliberately enabled. Legacy ETL URL/path helpers now use public-address validation, redirect checks, bounded responses, and a `data/` path boundary; DNS rebinding remains a residual risk. See `CLEANUP_AUDIT.md` for unresolved issues and security verification.

The FastAPI application lives in `app/`: `app/main.py` creates the API, `app/api/agent.py` exposes the agent-run route, `app/core/router_service.py` provides a mock-first injectable service, and `app/api/sql.py` exposes the mock-first SQL Analyst route backed by `app/core/sql_service.py`. `app/api/runs.py` exposes read-only recent/detail history endpoints backed by privacy-minimized SQLite records in `app/core/run_history.py`. Existing Workspace, ETL extraction/transformation, and SQL runs write generic outcomes; raw prompts and results are excluded. History is capped at 500 records. There is no user identity/authentication, so history is shared by local API callers and is not suitable for multi-user deployment without authorization. The API also provides `app/api/etl.py`: extraction (`POST /api/etl/extract`), transformation (`POST /api/etl/transform`), managed dataset listing (`GET /api/files`), paginated preview (`GET /api/files/{file_id}/preview`), and download (`GET /api/files/{file_id}/download`). Generated files and persistent `manifest.json` metadata are stored under `app_data/generated/`; IDs are server-generated and paths are validated within the managed root. CSV, JSON Lines, and Parquet are supported. API tests are in `tests/unit/`.

The React frontend is in `frontend/`, with `src/main.tsx` as its entry point. It provides `/`, `/etl`, and `/sql` routes through lightweight browser-history navigation and a typed API client in `src/api/client.ts`. The Workspace provides mock-first agent requests. `/etl` provides extraction, registered dataset selection, transformation mode controls, previews, pagination, and ID-based downloads. `/sql` provides a natural-language SQL Analyst UI backed by `POST /api/sql/run`; mock is the default and live execution also requires `ENABLE_LIVE_AGENTS=true` on the server. The Phase 5 implementation is fake-agent tested and build-verified, but browser interaction and controlled database-side read-only permission verification remain outstanding, so Phase 5 is incomplete. Set `VITE_API_BASE_URL` in a frontend environment file (example: `http://127.0.0.1:8000`); that variable is a browser-visible API URL, never a secret.

To run the frontend, from `frontend/` copy `.env.example` to `.env`, install the declared frontend dependencies with `npm install`, then run `npm run dev`. The Workspace defaults to mock mode. The live selector does not override the server gate; live use also requires the server process environment variable `ENABLE_LIVE_AGENTS=true`. External API extraction and live transformations require their explicit actions and controls. SQL mock requests do not generate or execute SQL; live SQL additionally requires explicit selection in the SQL Analyst and the same server gate. The TypeScript/Vite production build passes. Browser review confirmed the Workspace, navigation, backend connectivity, mock request rendering, and a narrow viewport without page-level horizontal overflow; frontend interaction tests are not configured, so Phase 2 remains incomplete. Phase 5 SQL browser behavior has not yet been verified.
